Интерактивный картографический веб-сервис для проектирования, редактирования, версионирования и анализа пешеходных маршрутов ежегодного физкультурно-спортивного мероприятия **«Майская прогулка»** (г. Екатеринбург и окрестности).

Проект разработан специально для организаторов и волонтёров мероприятия с целью автоматизации логистики маршрутов, расчёта характеристик покрытия дорог, привязки путей к реальной геосетке и подготовки пространственных данных к публикации.

---

## 🚀 Быстрый запуск (Локально)

Для работы приложения необходимы **Docker** (с Docker Compose) и плагин **Live Server** для VS Code (или аналогичный статический веб-сервер) на фронтенде.

### Шаг 1. Настройка переменных окружения
Создайте в корне проекта файл `.env` на основе шаблона и введите актуальные данные:
```bash
cp .env.example .env
```

### Шаг 2. Запуск Backend и Базы Данных (через Docker)
Бэкенд-сервис, СУБД PostgreSQL с расширением PostGIS и маршрутизатор OSRM запускаются в изолированных контейнерах одной командой:
```bash
docker compose up -d --build
```
*Данная команда автоматически:*
1. Соберёт Docker-образ для FastAPI бэкенда.
2. Скачает и развернет PostgreSQL с поддержкой PostGIS.
3. Проведет необходимые миграции базы данных через Alembic.
4. Запустит сервис маршрутизации OSRM с предзагруженными картами Свердловской области.

### Шаг 3. Запуск Frontend
Поскольку клиентская часть реализована на чистом JavaScript без компилируемых фреймворков, для её запуска достаточно любого статического веб-сервера.

1. Откройте директорию проекта в редакторе (например, в **VS Code**).
2. Нажмите правой кнопкой мыши по файлу `frontend/index.html` и выберите **"Open with Live Server"** (убедитесь, что Live Server настроен на работу на порту `5500`).
3. Приложение откроется в вашей системе по адресу:
   👉 **[http://localhost:5500/frontend/index.html](http://localhost:5500/frontend/index.html)**

## 📡 Примагничивание путей (Snap-to-Road) с помощью OSRM

Одной из ключевых сложностей при планировании пеших маршрутов является неровное ручное рисование треков пользователями и сложность ручного обхода изгибов дорог. В веб-приложении реализована **система автоматического примагничивания путей**.

### Как это устроено и работает:

1. **Запись «Сырых» Координат:** При включенном режиме «Примагничивание» пользователь кликает по карте, создавая последовательность условных опорных точек (маркеров).
2. **Запрос к OSRM API:** Фронтенд отправляет GeoJSON с координатами на бэкенд FastAPI, который проксирует запрос к локально развернутому сервису **OSRM (Open Source Routing Machine)** на эндпоинт `/api/routes/osrm/match` (используя алгоритм *Map Matching*).
3. **Радиус Поиска и Анализ Весов:** OSRM анализирует переданную ломаную линию и ищет в радиусе `OSRM_RADIUS_M` (по умолчанию 15 метров) реально существующие в OpenStreetMap дороги, тропинки, просеки или пешеходные пути.
4. **Математическая аппроксимация (Скрытая марковская модель):** Под капотом OSRM оценивает вероятность того, что пользователь шел по конкретному дорожному сегменту, учитывая расстояние от клика до дороги и топологическую связность дорожной сети.
5. **Возврат Сглаженной Геометрии:** OSRM возвращает массив точек, строго лежащих на реальной дорожной сети, огибающей ландшафт.
6. **Отрисовка:** Фронтенд мгновенно заменяет грубый отрезок плавной, красивой линией, идущей точно по лесной тропинке или тротуару.

#### Схема процесса:
```
[Клик пользователя (сырая точка)] ──> [Поиск ближайших дорог в радиусе 15м]
                                               │
                                               ▼
[Плавная дублирующая геометрия на карте] <── [OSRM Алгоритм Map Matching]
```

## 🛠 Технологический стек

### В клиентской части (Frontend)
*   **Vanilla JavaScript (ES6+):** Написание чистого, структурированного кода без излишней реактивной обертки, что обеспечивает моментальный рендеринг геометрии и оптимизирует нагрузку.
*   **OpenLayers:** Высокопроизводительная библиотека для работы с интерактивными картами. Отвечает за:
    *   Динамический рендеринг векторных слоев (маршруты, контрольные пункты КП).
    *   Инструменты интерактивного рисования линий (`Draw`), удаления сегментов (`Select` + `Modify`) и панорамирования.
    *   Работу со сторонними тайлами (OSM, Яндекс.Карты, Google Maps).
*   **HTML5 / CSS3:** Современная разметка с адаптивной боковой панелью управления, модальными окнами, формами авторизации и карточками статистики.

### В серверной части (Backend)
*   **FastAPI:** Легковесный высокопроизводительный асинхронный веб-фреймворк на Python. Используется для:
    *   Предоставления строго типизированного REST API.
    *   Быстрой валидации данных за счет интеграции с Pydantic.
    *   Автоматической генерации интерактивной Swagger-документации (`/docs`).
*   **PostgreSQL + PostGIS:** Объектно-реляционная СУБД с пространственным расширением. Хранит и обрабатывает географические объекты:
    *   Тип данных `Geometry(MultiLineString, 4326)` представляет физические треки.
    *   Пространственные индексы обеспечивают моментальную выборку пересечений и фильтрацию по полигонам.
*   **OSRM (Open Source Routing Machine):** Высокоскоростной C++ движок маршрутизации. Выполняет привязку треков и вычисляет оптимальные пешеходные графы.
*   **SQLAlchemy & Alembic:** Современный паттерн ORM для безопасной работы с таблицами БД и версионирования схемы данных с помощью миграций.

## 🎯 Ключевые возможности системы

1.  **Интерактивный редактор карт:**
    *   Режимы: «Рука» (навигация), «Кисть» (рисование), «Ластик» (разделение и удаление звеньев трека).
    *   Быстрое переключение картографических подложек для сверки дорог.
2.  **Полноценное API Маршрутов (CRUD):**
    *   Сохранение нарисованной ветки с вводом уникального названия.
    *   Редактирование ранее созданных путей с перезаписью пространственных данных в PostGIS.
    *   Объединение (merge) нескольких участков дорог в один сквозной трек.
3.  **Умная статистика и анализ покрытия:**
    *   Приложение автоматически классифицирует участки дорог, по которым проходит маршрут.
    *   Вычисляется протяженность асфальтового полотна, лесных и полевых тропинок, а также общая протяженность в километрах.
4.  **Безопасный доступ (Панель Администратора):**
    *   Обычные пользователи могут просматривать карту и изучать статистику.
    *   Создание, изменение и удаление маршрутов доступны только авторизованным пользователям (безопасные сессии на основе HttpOnly Cookie).

## 🐳 Конфигурация Docker Compose

Контейнеры оркеструются в единой сети. Вот базовая схема взаимодействия сервисов в файле `docker-compose.yml`:

*   **db**: Контейнер СУБД на базе `postgis/postgis:15-3.3` (порт `5432`). Инициализирует пространственную БД и хранит таблицы маршрутов.
*   **osrm**: Сервис маршрутизации на основе `osrm/osrm-backend`. Считывает OSM-карты из директории `/data` и предоставляет порт `5000` для map-matching.
*   **backend**: Наше FastAPI асинхронное приложение. Зависит от СУБД и OSRM, осуществляет миграции и проксирует запросы на порт `3000`.
